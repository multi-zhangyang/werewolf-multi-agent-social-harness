# 复盘工具只作一次策略选择

v12 固定两目标批次执行 176 次真实调用，两个目标都结束，没有模型失败；公共品终局有一次工具错误。模型调用 `finish_episode_review` 时填写 `status=ready`，同时把 `strategyIds` 留空。两项参数各自符合原生 schema，但组合违反业务规则，工具因此拒绝；模型下一步改为证据不足后完成。原错误仍计数，不能因后续纠正而删除。

问题是接口要求模型独立表达同一项决定两次。v13 的原生工具参数去掉 `status`，保留 `sourceIds`、`strategyIds` 和 `summary`。模型选择实际引用的策略，没有依据时选择空列表。程序在生成正式复盘记录时，按列表是否为空得到 `insufficient` 或 `ready`。这是从单一选择生成状态，不是改写模型发出的参数，也没有解析普通文本来伪造工具调用。

已有业务检查仍验证来源、策略是否有效且可迁移、重复引用，以及复盘只能提交一次；状态和旧记录格式继续兼容。用户界面保留“证据不足”和“可供后续检验”的区分。引用了有效策略只表示保留候选，不能当成已经学到新知识、改善回报或验证通用适用性。

两项新增本地 HTTP 测试通过官方 SDK 分别提交空列表和有效策略列表，检查模型实际收到的 schema 不再有 status，生成的状态正确，原心理未改写，且只提交一次。既有同次激活先提炼再复盘、预算预留和流失败回滚继续验证。新真实批次沿用原 v5 来源、原两个目标、原模型与所有预算和学习门槛，不覆盖此前 176 次调用或这次工具错误。
