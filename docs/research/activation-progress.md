# 官方 SDK 的逐步执行进度

完整响应超时修复后的固定批次 `data/strategy-application-validation-1791082340675` 执行 117 次真实调用，两个目标均未完成，出现两次 `incomplete / max_output_tokens`，没有工具参数错误。原失败保留。两次失败分别使用了 4041 / 4093 个推理 token，占满 4096 输出预算的大部分，均没有返回原生函数调用。

两次失败请求都有待完成的旧策略检验，因此世界动作工具未开放。模型输入中的原始进度只在激活开始时生成；工具的可用性随本地状态变化，初始的 `appraisalRequired`、`assessmentRequired` 却一直保留。信任失败响应的公开文本反复描述还未开放的返还动作。这些事实支持改善当前步骤说明，不能单凭两次失败证明全部原因在提示，或断言提高输出预算必然解决。

v12 通过官方 `Agent.instructions(runContext)` 提供动态说明。已安装 SDK 在每次模型请求前调用 `getSystemPrompt`，因此当前评价要求、当前版本的检验要求、精确策略编号、剩余步数及完成工具都会随本地状态更新。原始观察、证据、原生函数参数、工具回执与 Session 均由原有流程和 SDK 保留；没有新建工具循环，也没有把普通 JSON 文本解释成工具调用。

动作前仍须完成必要评价和旧策略检验；apply / adapt / reject 均合法，不强迫采用。修订使检验失效时，下一次说明重新列出待检验；停用最后一条候选后会移除该要求。最后一步的说明与 SDK 的完成预算保持一致。配置记录使用 `instructionPolicy=sdk-dynamic-progress` 区分旧版静态说明。

三项本地 HTTP 回归通过真实官方 SDK 核对：流式响应后的逐步说明、普通 JSON 响应后的修订重新检验、停用之后的完成状态。测试也检查初始观察保持原文、动作在正确阶段开放、旧版本采用不会转给新版本，以及最终只有一次提交。这些测试不代替真实模型验证。

下一批继续使用原 v5 固定来源、两个原目标、8 次模型步骤、4096 输出 token、60000 ms 完整响应时限及原学习门槛。它与 117 次失败批次分别保存，不自动重试旧请求、不修改旧结果，也不将工程回归通过视为通用心理或收益能力通过。
