# 经历提炼、适用性判断与策略反馈

## 要解决的缺口

前一批信息交易的预定源局保存了 6 条 `scope=episode` 条件策略。新环境正确地没有加载它们，因此这次条件策略迁移没有通过。不能改写这些旧记忆的范围来制造通过结果，也不能把自动保存的收益经历称为已经学会了可迁移策略。

心理状态 v4 在同一个 Agent 内加入经历提炼和行动前适用性判断；v5 补上整局私有复盘并收紧行动采用统计；v6 将明确检验作为取回旧策略后行动的前置条件；v7 补充实际动作、账本结算与个人解释的来源区分，并按结算分组，防止记录条数混作经历次数。执行器继续使用官方 Agents SDK、gpt-6-luna、256000 配置上下文和原生 Responses；没有额外的专家 Agent、人工策略选择器或模型权重更新。

## 研究依据与采用范围

- [ExpeL: LLM Agents Are Experiential Learners](https://arxiv.org/html/2308.10144) 区分经历收集、跨任务知识提炼和后续取回。本项目借鉴显式提炼及来源保留，不采用它收集阶段的反复重试，也不把它的性能数字当成本项目成绩。
- [CLIN: A Continually Learning Language Agent for Rapid Task Adaptation and Generalization](https://ar5iv.labs.arxiv.org/html/2310.10134) 将行动与条件之间的抽象关系保存在可更新记忆中，指出“下次去某张桌子”这类局部计划不等于通用经验。本项目用有适用边界的 when/then 表达待检验策略；观察关联不自动升级为已识别的因果规律。
- [Managing Procedural Memory in LLM Agents: Control, Adaptation, and Evaluation](https://arxiv.org/html/2606.23127) 的 AFTER 研究区分源任务提升与任务、角色迁移，并观察到窄经历产生的策略可能过度专门化。本项目据此单独记录来源、适用性判断、实际采用和后续结果。
- [How Memory Management Impacts LLM Agents: An Empirical Study of Experience-Following Behavior](https://aclanthology.org/2026.acl-long.27.pdf) 讨论错误传播与不匹配的经历复用。本项目不把检索到的规则作为必须执行的指令；人物可以拒绝采用，反馈只由世界账本记录。

检索结果与正文片段保存在 `data/general-agent-research/consolidation-1791067565592/`。这些方法为实现提供依据，不构成本项目的行为验证。

## 实现契约

1. `consolidate_strategy` 只可引用本人当前可用、具有可见结算来源的经历记忆。它创建新的可迁移条件策略，保留源记忆 ID、版本和提炼理由；不会修改原经历、本局判断或历史失败。
2. `when` 描述可以复用的条件及边界，`then` 描述可尝试的行动原则。具体游戏身份和工具参数继续由当前环境决定。提炼结果是模型提出的假设。
3. 工作记忆为条件策略、相关经验和近期记录留出位置。检索仍采用 Unicode 词面排序；没有声称使用向量检索或可靠语义理解。
4. `assess_strategy` 必须引用当前情境证据，记录相符条件、关键差异以及 apply / adapt / reject。它不调用世界动作。采用或调整后，只有随后成功提交的动作才会关联到该检验；拒绝、已停用或已被修订替代的版本不会被计作采用。
5. 收益和预测评分仅由之后匹配的世界账本事件回填，保持原始来源。检验记录保存采用时的策略版本和文本，当前版本统计不继承旧版本成绩。关联结果不证明策略造成了收益。
6. 跨局输入排除旧局身份、局部判断和旧局适用性分析。研究历史保留原文。新工具与心理、动作一起暂存；后续响应失败时整次激活均不提交。
7. v5 的调度器在世界结束、全部实际结算完成后，逐个调用同一生产 Agent 作私有整局复盘。输入提供本人整段实质行动、结算经历与概率预测，禁止世界动作、通信和旧式直接写入。`finish_episode_review` 引用当前有效策略及版本，或保存 insufficient 的理由。ready 只表示可供后续检验。
8. 新策略在同次激活中生成时，结束工具根据当前记忆数组精确解析其 m 编号；不猜测或补正模型参数。复盘通过 SDK 和事务后才允许生成最终快照。未正式提交、持久化失败或取消均不能推进快照；真人和旧实验参与者不增加复盘负担。
9. 实际采用要求同一机会随后提交实质世界动作。讨论中的意向、发言或等待不算行动采用；旧 v4 的错误关联保留在历史，当前展示和统计不将它用于行动采用指标。
10. v6 在实质行动机会中发现取回的旧可迁移策略时，要求至少明确检验一条当前有效版本；SDK 的 `isEnabled` 与执行阶段 `ready()` 共同检查。apply / adapt / reject 均合法，不规定动作。修订后必须重新检验当前版本；以前机会的判断不能替代本次判断。明确停用或改为非策略记忆也会保留来源和理由，不被计作策略采用。
11. v7 的自动经历保留已提交的实际动作参数和原结算，标明账本来源；人物自己写入的记录单独标明。提炼输入按结算 ID 去重分组，分别统计结算次数和记录条数，保留全部源笔记及源版本。事实分组正确不等于模型解释正确，仍需人工核对新策略内容。
12. v8 为结算后补偿单独记账，轮内收益不能关联旧轮动作；被动接收也保留实际回报。整局胜负可以覆盖多轮，动作记录仍保留原轮次。该归属修复来自真实 v7 失败，原失败、错误关联与模型角色混淆的文本都保留，详见[反馈归属](feedback-grounding.md)。
13. v9 通过 SDK isEnabled 为未完成的评价、检验和结束工具保留步数。只剩必需步骤的预算时，不再提供计划修改或回忆等可选工具；需要旧策略检验时，schema 限定为取回的候选。原 8 步预算、拒绝选项和事务边界保持不变，详见[完成预算](completion-budget.md)。
14. v10 的提炼工具只暴露一个经历选择字段；结算来源从这些经历与本人可见账本的链接确定并去重，取消可互相矛盾的结算选择。模型仍决定提炼内容、条件、置信度和边界；原始模型参数不重写，原经历不修改，详见[提炼来源](consolidation-provenance.md)。

狼人杀观察同时澄清它是桌面身份游戏，规则动作只改变局内玩家状态。没有关闭、忽略或重写提供商过滤结果；过去的 content_filter 失败仍保留。该说明的稳定性影响需要新的真实运行验证。

## 验证要求

确定性检查覆盖来源关联、不可用记忆、重复引用、旧身份隔离、词汇变化下的取回、拒绝与旧版本不被采用、真实未来反馈、版本统计隔离、原生 SDK 回执与失败回滚。界面显示提炼理由、适用性判断、实际采用及账本结果，夹具不计作真实模型行为。

真实验证在运行前固定于 `scripts/validate-strategy-learning.ts`：两条从新心理状态开始的信息交易来源（种子 23、41，内置人物 01 与 03，利益冲突，每局 4 轮）。种子 23 的发送者为 01，之后两人进入 3 轮信任交易；种子 41 的发送者为 03，之后两人和新人物 02 进入 3 轮公共品。每次激活最多 8 个模型步骤、4096 输出 token、单请求 60 秒。新场景仍使用相同生产 Agent，新增人物从新状态加入。来源条件不按行为挑选，没有人为旧判断或固定策略对手。分别记录是否提炼、是否取回、是否检验、是否实际采用、是否获得后续账本反馈、是否修订，不用其中任何一项代替另一项。预定源局缺少已完成快照或提炼策略时，目标局记录 not_started，不能改选来源。

另运行一场独立的 6 人、种子 23、两天期限狼人杀，核对当前执行内核与规则说明。它不重试或改写旧失败对局。所有批次必须保留源码快照、实际 HTTP 输入、call_id 回执、原始失败和激活提交记录。行为能力与协议通过分别判断；小批次不能证明可靠欺骗或普遍收益优势。
