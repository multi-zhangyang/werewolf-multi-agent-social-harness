# 持续策略修订与预测复盘

v10 的真实记录中，相近的条件策略常在结算后重复新增。原提炼工具只能创建，修订需要转到另一个参数结构；复盘还出现将行动预测称为收益预测、把同一事件的两条预测算成多次观察、把未评分预测称为失败的情况。v11 以同一套官方 SDK 执行这些改进。

`consolidate_strategy` 增加必填可空的 `strategyId`：同一原则的补充证据、边界或反证选择原编号；不同原则使用 null。已覆盖且无需改变的原则可以直接复用。可选编号来自本人当前有效的可迁移条件策略；输入同时列出这些策略的当前内容和来源局。系统不做语义自动合并，也不代替人物选择策略。

结算来源仍仅由 `memoryIds` 所选经历与本人可见账本的精确链接派生。更新保留原 ID，增加版本，将旧内容和旧提炼来源保存在历史中；实际经历不可改写。一般 `revise_memory` 更新不沿用旧版本的提炼元数据，防止旧来源被误认成新版本来源。稳定来源局沿首版记录追踪，不因新内容写在目标局就丢失继承关系。

修订使旧版本的检验失效；新版本须在当前行动机会重新检验，旧采用与旧收益不计入它。临近预算上限时，修订可能额外需要一次检验，工具可用性因此先预留该步骤。四组原生 SDK 边界回归覆盖第 6 步修订后检验并行动，以及仅剩两步时不再开放可能使检验失效的修改，均保持 8 步上限。

`predictionFeedback` 只读取本局正式记录：分别统计行动与结算预测、已评分条数、按评分来源分组的事件数和未评分条数。正式评分须同时有布尔结果、来源 ID 与有限 Brier 值。终局未评分项显示为未验证，不补写 result 或误差。终局复盘在 `finishEpisode` 之前发生，因此显式使用结束状态生成反馈；旧局预测仍保存，但不混入本局普通预测输入。

设计参考此前检索的 [CLIN](https://arxiv.org/abs/2310.10134) 中跨试验更新经验的思路和 [A-Mem](https://arxiv.org/abs/2502.12110) 中记忆演化的思路。这里只借鉴持续修订方向，没有复现论文系统，也没有使用论文结果作为本项目成绩。SDK 依据仍是已安装的 `@openai/agents 0.16.0` 与实际原生请求。

隔离副本通过 267 项测试、lint、类型检查、生产构建与验证脚本类型检查。固定五个 v10 终局前状态的独立实验执行了 14 次真实调用：4 次更新原策略、1 次记录证据不足、零新记忆、零工具错误。它是旧状态的单独替代复盘，没有覆盖原对局或追加到原对局历史，也不能证明后续行动采用。

人工检查全部 5 次复盘和 4 次策略更新后，内容质量仍未全部通过：信任复盘有收益角色标签混用，一条更新后的策略文本把两次受托结算写成三次，另有“独立结算”的措辞不严谨。正式来源与预测反馈正确不能保证自由文本正确。原请求、错误文字和独立审查保留在 `data/memory-reconciliation-validation-1791078960151` 与交付目录的 `review-content-audit.json`。

完整跨场景验证继续使用原 v5 的两份固定源快照、原两种目标场景和原学习门槛；结果另见[验证记录](../validation-native-responses.md)。
