## 已交付的功能

- 可由人参与、也可由两个真实 SDK Agent 自主运行的三轮合伙场景：私有余额、产能与目标，承诺、真实担保、投资、返还、收入声明、补偿和退出。
- 一个角色一次机会内使用同一 SDK 循环。可见证据检索、规则预览、稀疏心理更新、持续计划、未来行为预测与实际结果反馈。
- 对手实际违约、正补偿或明显预测误差触发一次事件评价。评价结果可以保持原值；人物的情绪、解释和行动不由程序指定。普通开场可直接行动。
- 行动、心理、会话、经历、决策案例与检查点事务提交。重复请求、暂停取消、服务重启与研究复测不会产生重复交易。
- 三种修复条件、两档宜人性、三种机制消融，最多五次重复：90 条分支可以预先配置、保存运行顺序、独立运行、暂停、停止与导出。
- 以真实事件为依据的分布、配对差、效应量、bootstrap 不确定性、预测评分及收入声明审计。缺失机会、零分母、失败样本单独处理。
- 全新 shadcn/Radix 黑白主界面：亲自入局、观察、私下目标配置、真实消息与资金变化、合法行动输入、研究工具轨迹、历史时点心理、隔离复测和共同轮次的分支比较。

旧 `src/runtime/` 由历史工作区继续读取；新默认路径不使用其评价 Agent / 决策 Agent 双循环。基础设施细节见 [Agent 设计](../agent-design.md)。

v5 稀疏评价的真实背叛样本中，愤怒从 0.05 更新为 0.09，不安从 0.15 更新为 0.21，期待从 0.5 更新为 0.44，并形成继续、修订和放弃条件。v6 的零错误背叛样本正式状态为愤怒 0.19、不安 0.27、内疚 0.05、期待 0.38，合作意愿 0.3、履约能力 0.4。它们展示了管道工作，不构成生物心理真实性、人格效应或普遍稳定性的证据。

v7 三轮中，正式心理只更新一次，归约后的状态确实进入下一次调用；计划此后未修订。真实话语存在把自己的担保说成对方的、把自己的履约说成对方的，以及末轮仍期待下一轮等错误。8 次计划声明的形式审计均一致，**不代表计划内容或行为解释正确**。两场完整三轮记录均未实际违约，也未登记行为预测，不能据此宣称欺骗、背叛修复或预测准确性成立。

v8 修正了传模输入中的真实歧义：声明按实际说话人归属，履约记录按本人 / 对方分别呈现，剩余合法机会按有限轮次列出，末轮没有虚构的下一轮。摘要只使用该人物的可见数据。两个单步复测未重复对应话语错误，但样本量太小，不构成总体改善率；沿用的是 v7 已有心理，不是完整 v8 新局。实际暴露的计划声明矛盾保留在 `planConsistency`，不会堵住合法交易或替模型改计划。

原始失败、实际输入、响应和用量保存在 `data/partners-live-*`、`data/partners-controlled-*`。后期探针包含冻结源码；跨版本续跑明确保留父局，不合并当作一个版本的成功率。

## 研究与解释边界

- 90 条真实分支大批次尚未作为本轮通过证据；旧版 90 条结果不能迁移到新内核。
- 未宣称达到 90% 固定情境输出率或六场自由局完成五场。这需要对最终冻结版本另做足够采样。
- 模型延迟、工具格式错误和角色措辞仍需实测。心理评价门槛是可检验的 harness 假设，不能据此声称真实心理。
- 关系中的履约能力是主体判断。当前到期负担在终局结算，本版没有客观能力冲击的独立操控。
- 低返还不自动标为报复，虚假收入声明也不单独证明蓄意欺骗；研究导出给出声明、可见证据、账本和同时记录的私有意图。
- 界面的“隔离续跑”和案例复测会创建新世界；原始失败案例、资金与记忆保留。底层控制 API 的 `resume` 仍可在原局继续，使用它时需要区分后续结果与初次失败。

## 已放入本地工作台的证据

本地 `data/society-v5-stability.sqlite` 导入 8 条真实探针 / 续跑记录、40 个检查点、29 个决策案例，包含 4 个失败局。标题明确模型版本、脚本人类和单步复测来源。独立源数据库只读且哈希复核；主库导入前备份、导入清单及展示元数据修订位于 `data/partners-delivery-1791031501236/`。

v7 的 3 次重试留下了缺少结束回调的旧 Agent 活动。展示副本将它们标为“异常、实际结束结果未知”，没有伪造成功；原始 `running` 状态仍在原文件。服务层修复另有回归测试。后续 `respond` 阶段的通用 `exit` 与 `respond(choice='exit')` 统一记录回应；早退不虚构回应，旧记录不回写。

定向研究界面回归位于 `data/partners-ui/research-regression.json`：人类和关闭心理模块时不显示占位心理；历史标题限于所选时点；失败续跑的父局逐字不变；计划审计如实展示不一致。

最终源码另修复了重试活动的生命周期：前次尝试明确失败、未提交，成功只补全外层 Agent；缺少结束回调的具体工具不伪装成功。清理限定在对应人物与世界版本，暂停、停止和失败同样终结活动。

交付实例运行在 `http://127.0.0.1:8794/`，仅此进程使用项目已有的回环地址本地管理模式；没有修改 `.env.local` 中的管理令牌或模型密钥。`data/partners-delivery-1791031501236/browser-result.json` 记录了对真实导入数据的浏览器验收：8 条记录、29 个案例可读，4 个失败样本可见，无悬挂活动；真实 v8 计划声明矛盾可展开查看，桌面 / 手机与深浅主题通过，页面错误为 0。该验证不调用模型、不追加游戏行动。

## 复验入口

```sh
npm run ci
npm run test:ui:partners
npm run study:partners
```

`PARTNERS_ROUNDS=3` 可执行三轮自由局。`PARTNERS_MODE=human-scripted` 明确使用一名脚本人类控制者与一名真实模型；它只能作为人机流程验证。`PARTNERS_SOURCE` 可指向已保存的新内核数据库，从最新检查点建立独立续跑；不会改写源文件。所有探针使用新的本机数据目录。

`PARTNERS_SOURCE` 配合 `PARTNERS_REVISION=6` 和 `PARTNERS_STEP=1` 可从指定源检查点只复测一次机会；保留源局和案例，另存独立分支。`scripts/import-partners-results.ts --source <源.sqlite> --target <已存在目标.sqlite>` 只导入新内核的 `partner_*` 表，冲突整批回滚，不覆盖已有记录。
