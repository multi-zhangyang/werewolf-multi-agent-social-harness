# Agent 设计（SDK harness 与心理干预）

本项目的 Agent 由模型和应用 harness 共同构成。模型提出解释、表达与选择；harness 管理可见事实、持续心理、会话、工具能力、执行预算、提交与研究证据。不能只靠更长的人格提示词或替换模型改善代理行为。

独立混合实验可通过 `RunSpec.psychologySetup` 为每个 AI 注入初始情绪、关系估计与私下目标。初态在第一次激活前进入正式状态，并明确记为研究者干预。后续心理归约与实际决策沿用同一状态；目标仅进入对应主体，不进入对手观察。承诺前额外记录 `commitmentIntent`，供研究者对照公开承诺和真实结算，不强制选择金额。入口、权限和完整对局证据见 [v7 基础验证](research/foundation-v7.md)。

## 一次机会怎样运行

1. 规则引擎提供本人可见的事实、当前角色、阶段和合法行动。参与者的话始终是说法，不是到账证明。
2. 开启心理模块时，单次评价 Agent 只能调用 `update_mind`。混合模式通过惯性归约保存正式状态，然后把正式状态交给决策 Agent。评价 Agent 不代人物发言或交易。
3. 决策 Agent 通过 SDK `Runner` 循环选择检索、记忆、交流或领域工具。`HarnessContext` 经 SDK `RunContext` 传入，记录本次机会、正式状态、已提交动作、尝试次数和步骤。
4. `callModelInputFilter` 在每次模型请求前更新进度与正式状态，不剪断工具调用/结果配对。规则引擎仍是账本与权限的最终裁判。
5. 必需行动提交成功即从动态工具集合中撤下；混合模式、显式认知配置及开启心理的模式在全部动作完成后结束机会。旧版无心理、无认知配置模式保留动作后最终回复，以便旧档案行为定义可理解。

## 工具循环的边界

- `tool.isEnabled` 每一步重新提供可用工具。剩余步骤小于等于待提交动作数时，关闭记忆与检索；交流至少预留最后一步回复或 `wait`。两次空检索后关闭本次机会的检索。
- 工具 input guardrail 在执行前再次检查是否已结束、是否重复提交、是否占用预留步骤。相同人物与同一组关键词的重复检索被拒绝，模型可以转向决策或提出新疑点。
- `parallelToolCalls: false` 是提供商约束；SDK `maxFunctionToolConcurrency: 1` 保证本地工具串行。即使异常响应包含两次交易，第二次也不能重复扣账。
- `toolUseBehavior` 根据正式提交结果结束调用。没有把合作、报复、金额或发言内容写进工具路由；预留步骤不能保证模型一定遵守，缺失行动仍保留为失败。
- 心理与决策维持一次评价、再决策的结构；没有增加多层心理角色或预演循环。

## 会话与记忆不是同一种状态

服务端通过 SDK `Session` 接口把会话保存到增量 SQLite 表 `sdk_sessions`。键包含 harness 版本、对局/分支、人物、阶段和用途；独立分支不会读写源会话。未传存储工厂的隔离单元测试使用 `MemorySession`。

所有决策模式现在使用 session，混合模式不再绕过它。混合/显式认知配置只带入同阶段最近一次完整激活；旧用户输入替换为历史标记，防止旧账本和旧心理与当前事实竞争。超过 compact 8,000 / expanded 16,000 字符的历史激活整体移出输入；当前事实、来源和正式心理保留。此上限是工程字符预算，不是精确 token 计数。旧模式保留最近两次完整激活。阶段切换后从本人可见事件重新组装。

心理评价刻意不复用旧评价的 SDK 对话；它从最新前态和事件构建输入，原请求、响应保存在 `DecisionCase`。长期记忆仍是具有来源、归属和对局信息的经历/观点；SDK 会话不代替它。跨局心理通过已完成快照继承，关闭关系记忆阻止跨局继承。

SQLite session 使已保存的同阶段会话在重新创建 participant 后可读；这不等于崩溃时正在执行的工具可以安全续跑。目前重启仍将未完成局标为 interrupted，不自动重放交易。后续若接入 `RunState`，必须同时实现机会与工具事务恢复协议。

## 失败、用量与可观测性

Cardinalize 的 `apodex/apodex-1.1-mini:free` 保持不变。心理、交流、行动分别读取配置的思考强度和输出预算。未显式配置的传统模式交流用 low、行动用 medium；认知配置优先。HTTP client `maxRetries: 0`，没有后台网络重试。

提供商响应经过 `bufferedModel` 检查后 SDK 才能执行工具；截断和坏 JSON 不修补、不提交。未提交的可重试失败最多一次显式重试，恢复尝试前会话并清除该次检索控制状态。任何成功写入心理/记忆/消息/行动之后都不能从头重放该机会。每次响应的实际用量与每次失败分别保留。

SDK `agent_start/end`、`agent_tool_start/end` hooks 与模型边界记录尝试、步骤、callId、参数、返回、错误、耗时。`DecisionCase` 记录同样的 harness 版本、尝试与步骤，以及源码摘要和脱敏的完整模型输入。UI 用现有官方 shadcn Message/Bubble/Collapsible/Badge/Table 展示真实状态；同一调用的开始与结束合成一张卡。

日志只写本地研究权限数据，不进入参与者观察。SDK 外部 tracing 继续关闭；没有把私有心理发到默认 tracing exporter。工具拒绝与失败不会标成成功。

## 当前证据和限制

新的运行控制通过真实 SDK 配合假提供商的回归测试验证；这些测试验证执行不变量，不证明自然度或人格效应。真实小规模复测及质量问题见 [harness v6 验证](research/harness-v6.md)。旧版 90 分支与六场自由局属于旧源码，不作为 v6 成功率。

本轮尚未加入 RunState 崩溃续跑、跨主体 handoff、HITL 或额外心理 asTool。handoff 会改变当前主体所有权；asTool 会增加新的认知与信息边界，应在明确研究假设后使用。最有价值的下一步是把角色/轮次理解错误做成可复现的 harness 评估案例，验证是否因上下文选择与工具契约而改善，而非增加无法归因的内部角色。
