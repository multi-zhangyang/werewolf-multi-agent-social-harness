# 行动的反馈归属与补偿结算

v7 的固定真实信任局 `e2e22919-1f22-4e5f-8cc9-1c845adca326` 使用源码 `075196fa101fcb758fca31cbdfe4ee128c04186c63629e50670de26a8a9ad0e4`。该局完成 139 次原生模型调用，调用与工具参数错误均为零，但原结算核验失败。

第 1 轮的 repair_transfer 发生在主结算之后。适配器只改变累计分数，没有给它提供独立的收益事件；心理 reducer 又用 `decision.round <= outcome.round` 匹配所有待反馈动作，因此把这次补偿塞进第 2 轮收益。同样的问题在第 2 轮重复，最后一轮补偿则没有任何反馈。两个跨轮错误关联和一个缺失反馈均保留在原数据库，诊断见 `data/grounded-memory-delivery-1791073597541/failure-diagnosis.json`。

这项检查也发现两个人物在策略或总结中混淆了轮换的投资者、受托者角色。原始动作参数和来源 ID 正确并不保证模型解释正确；当前没有把模型文本的自信程度当作事实验证。

## v8 修复

- 轮内经济收益只关联同轮尚未得到反馈的动作，缺失的旧轮反馈保持缺失，不能借下一轮收益补齐。
- 补偿以独立账本事件记录转出和收到的增减，包含轮次、金额、双方得分及 `settlementKind=repair`。金额为零仍记录选择，且不重新计算前一笔交易收益。
- 没有本人新动作的回报也保存观察，动作列表为空；不把被动接收伪造成主动行为。资金、双方记忆和事件共用原事务，失败时一起回滚。
- 整局终局通过 `reward.scope=episode` 明确覆盖前面轮次，保留各动作真实轮次；经济反馈为 round 范围。通用 reducer 不包含某个游戏的策略选择。
- 信任主结算保存当轮投资者、受托者、投入和返还，并在结算文本标明角色。狼人杀终局写入实际天数。旧记录不被回写为新版事实。

## 验证与边界

250 项确定性检查及完整构建通过。以同一 v7 记录的实际动作在新规则中重放，3 次主结算与 3 次补偿分开，12 个动作均归属正确，两人累计回报与原最终分数一致；原数据库不变，重放没有调用模型。非零补偿、零补偿、被动接收和持久化失败分别有规则与集成检查。

新的真实验证继续使用原定 v5 来源快照，不重新选择有利来源，不修改旧失败。原协议、明确检验和实际采用反馈门槛不变；增加每笔可见回报恰好一条观察及同轮动作的核对。独立协议审计和工程通过仍不等于学习能力通过，真实结果见[验证记录](../validation-native-responses.md)。
