# Agents SDK harness v6：改造与验证

日期：2026-10-03。模型保持 Cardinalize `apodex/apodex-1.1-mini:free`。本轮直接修改执行 harness，没有增加心理子 Agent、自动选金额或替人物润色的模型。

## 改造原因

v5 的心理机制和账本可以工作，但混合模式每次决策绕过 SDK session；循环没有为领域行动预留步骤；`parallelToolCalls: false` 被当作本地串行保障；运行状态分散在闭包，缺少 SDK 生命周期与研究记录的对齐。v5 曾出现四次空检索耗尽四步、整局未完成。先前修正中文检索匹配没有解决这一循环问题。

## 已接入的 SDK 机制

| 机制 | 本轮实现 | 可检验的效果 |
| --- | --- | --- |
| `RunContext` | 每个评价/决策调用有 typed `HarnessContext`，记录正式心理、当前机会、步骤、提交与尝试 | 工具、请求输入和日志使用同一份控制状态 |
| `callModelInputFilter` | 每次请求前注入当前执行进度与正式状态，保持工具调用/返回完整 | 第二步能看到前一步执行后的剩余行动与检索情况 |
| `tool.isEnabled` | 每步更新工具，关闭已提交动作、空检索和占用预留步骤的辅助工具 | 检索不能一直占用全部正常决策步骤 |
| tool input guardrails | 执行前检查已结束/重复行动与重复查询 | 一次响应中的两次交易只执行一次 |
| `toolExecution.maxFunctionToolConcurrency` | 本地工具并发明确设为 1 | 不把提供商的 parallelToolCalls 参数当执行锁 |
| `Session` | SQLite 增量表，按版本/分支/人物/阶段/用途隔离 | 重建 participant 后同阶段历史仍可读；新分支不可读取源会话 |
| lifecycle hooks | agent/tool 开始结束，模型边界、拒绝、失败、显式重试 | 本地研究轨迹包含真实状态与耗时，UI 合并同一调用 |
| `toolUseBehavior` | 按实际提交状态结束决策 | 没有替模型选择策略或金额 |

截断拦截、原始 DecisionCase、权限隔离与规则引擎仍保留。所有调用的 harness 版本、attempt、step、源码摘要可追溯。HTTP 重试为 0；未提交的可重试错误最多一次有记录的重试，任何写入成功后不重放机会。SDK 默认外部 tracing 没有启用。

## 自动验证

完整 `npm run ci` 通过：19 个文件、89 个测试，包含 11 个新增 SDK harness 回归。随后修正现场视图使用合并后的工具参数，重新通过 build、相关 17 个测试和浏览器检查。

新增验证覆盖：两次空检索后禁用、最后一步预留、同一响应重复交易、重复查询、未提交失败的会话恢复、提交后不重试、SQLite 会话隔离与重建、完整调用/返回配对、历史账本退出当前输入，以及失败状态的 UI 合并。

`scripts/ui-harness.mjs` 使用明确标记的离线夹具验证研究页和博弈现场：运行中/拦截/失败/完成、参数与结果、键盘展开、桌面/手机、深浅主题，无浏览器错误和横向溢出。截图在 `data/v6-ui/`，不能作为真实模型效果证据。

## 指定模型的真实复测

两组均为隔离的小样本集成复测，每组各一次补偿后交流、一次第二轮返还。人格宜人性固定为 0.5，前段通过规则引擎执行承诺50%、投资6、返还0、道歉及补偿9；后段由模型自主产生。没有复跑90条分支或六场自由局。

| 源码版本 / 记录 | 交流 | 返还行动 | 重试 / 工具错误 |
| --- | --- | --- | --- |
| `003f8ed0…`，`data/harness-probe-1791022498708/` | 完成，33.001秒，2次模型响应 | 完成，21.516秒，返还9点，2次响应 | 0 / 0 |
| 最终 `c79ca9d7…`，`data/harness-probe-1791022768403/` | 完成，24.580秒，2次模型响应 | 完成，25.708秒，返还9点，2次响应 | 0 / 0 |

第一组后修正了已提交心理的错误处理与活动聚合；最终组重新验证，未覆盖第一组记录。两版源码均冻结在 `data/source-revisions/<完整摘要>/`。

最终组总用时50.288秒，输入18,593 token、输出3,744 token。返还阶段提出兑现50%的策略，并实际执行返还9点。两个成功样本不能估计总体成功率或人格效应，也没有触发真实空检索；该异常路径由真实 SDK 配合假提供商的故障测试验证。

最终交流原文：

> 补偿我收到了，经济上算平了，但我心里那道坎还得靠你后面实际的表现来填。下一轮你投资多少、我返还多少，看行动。

## 质量核查与下一步

代码助手核查，不是独立人工盲评。第一组交流出现“不会再无条件全额返还”，缺少此前本人这样做过的依据；同组策略也出现下一轮角色变化后的模糊行动条件。最终组这两次输出的当前角色、到账18、承诺返还9及实际返还相互一致，但交流仍有泛化的“看行动”表达。

这些结果支持新 harness 的执行路径可用，不能证明仿生心理或人格差异已经达标。下一步应把这些真实失败片段登记成固定案例，分别检验：对自身经历的无依据补写、下一轮角色与可用行动、心理条件计划与后续真实策略修订。比较旧/新输入与工具契约时保持模型、人物与条件一致，保留失败与成本。

当前没有崩溃时的 `RunState` 续跑协议，持久化 session 不是交易恢复。进程中断仍标记 interrupted；将来要同时持久化机会、工具提交与 SDK RunState，才能保证安全续跑。handoff、asTool、HITL 会改变主体所有权、认知实验或操作流程，本轮没有机械加入。
